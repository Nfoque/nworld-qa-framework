# QAAP — Domain Model

## Entity Relationship Overview

```
Tenant (1) ──── (*) User
  │                  │ created_by / assigned_to
  ├── (*) ConnectorConfig
  ├── (*) LLMProviderConfig
  │
  └── (*) TestPlan
        │
        ├── (*) ContextSource
        ├── (*) TestScenario ──── (*) GeneratedTest
        ├── (*) PlanConversation ──── (*) Message
        ├── (*) Execution ──── (*) ExecutionResult
        ├── (*) CronSchedule
        └── (*) ProactiveFix
```

### TestScenario

A single test scenario within a plan, in Gherkin format.

| Field | Type | Description |
|-------|------|-------------|
| id | UUID | |
| tenant_id | UUID | RLS |
| test_plan_id | UUID | FK → TestPlan |
| title | string | Scenario title |
| gherkin_text | text | Full Gherkin (Feature/Scenario/Given/When/Then) |
| confidence | float | 0.0 - 1.0. LLM's confidence in correctness |
| rationale | text | Why this confidence score |
| source_model | string | Model that generated this scenario (e.g., `claude-sonnet-4-20250514`) |
| review_model | string? | Model that reviewed (if second opinion was used) |
| review_feedback | text? | Review model's feedback |
| review_status | enum | `pending` / `approved` / `rejected` / `modified` |
| sort_order | int | For manual reordering |
| version | int | Incremented on each edit |
| created_at | timestamp | |
| updated_at | timestamp | |

**Rationale for `source_model` + `review_model`**: Enables the "second opinion" provenance trail. UI shows "Generated by Claude Sonnet 4, reviewed by Gemini 2.5 Pro".

**Rationale for `confidence`**: Drives routing — >=85% auto-approve, 60-84% human review, <60% manual. From `research/patterns.md` (5 independent sources converge on confidence as mandatory output).

## RLS Policy (applies to ALL tables)

Every table with `tenant_id` has this policy:

```sql
CREATE POLICY tenant_isolation ON <table>
  USING (tenant_id = current_setting('app.current_tenant')::uuid);
```

The Fastify `onRequest` hook sets `app.current_tenant` from the authenticated user's organization, so application code never needs to filter by `tenant_id`.
